Amitabh Chondro Roy — website (rebuilt from source)
===================================================

This folder is the PRODUCTION BUILD. Upload its contents to `public_html`.

Generated by `npm run build` from the real source project. The previous
`dist.zip` was broken because its build emitted JSX referencing an undefined
`React` symbol and a stylesheet with no Tailwind utilities. Neither can happen
here: the project builds with `@vitejs/plugin-react` and `@tailwind utilities`.


UPLOAD
------
1. Back up the current `public_html` first.
2. Upload the *contents* of this folder (not the folder itself).
3. Overwrite existing files. Asset names are content-hashed, so returning
   visitors get the new bundle instead of a cached one.
4. Clear the Hostinger cache, then hard-reload (Ctrl+F5).

`.htaccess` is hidden in Windows Explorer — enable "View > Hidden items" or use
FileZilla with "Force showing hidden files". It carries HTTPS, the www ->
non-www redirect, caching, compression and SPA routing.

The canonical host is https://amitabhroy.bd (no www). If you ever switch to
www, change it in three places together: the `www` rule in `.htaccess`,
`siteUrl` in `src/components/SEO.tsx`, and `public/sitemap.xml`.


WHAT THIS BUILD FIXES
---------------------
Build integrity
  * Built with @vitejs/plugin-react — no "React is not defined" crash.
  * Tailwind utilities generated properly (the old app.css had only the reset
    plus Quill's editor theme).
  * Route-level code splitting. The old 1.27 MB single bundle is gone.
  * Supabase and the Quill editor have been removed completely. The journal is
    now built from Markdown files and the contact form posts to Web3Forms, so
    there is no database that can pause, be deleted or need a keep-alive.

Retired pages (Oct 2026)
  * /cv is no longer a page. It 301-redirects to /about#cv, where the CV
    section already lives. The PDF at /cv/... still downloads.
  * /photography is no longer a page. It 301-redirects to /work#photography.
  * Navigation is now Home / About / Work / Research / Contact. The header
    collapses to the menu below 768 px.
  * .htaccess carries the 301s; the React router repeats them so deep links
    still work on hosts without mod_rewrite.

Photography gallery (on /work)
  * Five photographs are now in the gallery: Where the Sun Rests, Stillness in
    Bloom, The Beauty of What Remains, Where Light Finds Its Way and A City
    Lost in the Mist.
  * Masonry columns (1 / 2 / 3 by width) keep each photograph's native aspect
    ratio. Images are WebP at 640, 1024 and 1536 px with srcset + sizes, lazy
    loading, async decoding, intrinsic width/height, and descriptive alt text.
  * To add more: export the photo, generate the three WebP widths into
    public/photography/gallery/, then add one entry to src/data/photography.ts.
  * Category filters: All / Architecture / Urban Life / Landscape / Nature.

Research dashboard (on /research, updated to the Chapter 5 dataset)

Journal and contact form (Nov 2026)
  * The journal is no longer a database app. Each post is a Markdown file in
    src/content/journal/ and is compiled into the build. Nothing is fetched at
    runtime, so /blogs works even if every external service is down.
  * Create a post with `npm run journal:new -- "Title"`, edit the file, set
    `draft: false`, then `npm run build`. See src/content/JOURNAL.md for the
    frontmatter and the supported Markdown.
  * The contact form posts to Web3Forms (250 messages/month free, unlimited
    domains). Create a key at https://web3forms.com, put it in `.env` as
    VITE_WEB3FORMS_ACCESS_KEY, and rebuild. Until a key is set, the form falls
    back to opening the visitor's mail app with the message pre-filled.
  * The CSP now allows only https://api.web3forms.com for form submissions.
  * /admin, /admin/login and the other admin routes redirect to /blogs. There is
    no login, no database and no server-side state to maintain.

STILL OPEN (content, not code)
------------------------------

   `src/data/photography.ts` (see the comment at the top of that file).
2. The journal is empty until the first Markdown post is added. See
   `src/content/JOURNAL.md`, or run `npm run journal:new -- "Title"`.
3. The contact form needs a Web3Forms key in `.env`
   (`VITE_WEB3FORMS_ACCESS_KEY`). Without it the form opens the visitor's mail
   app instead of sending silently.
4. Images total ~10 MB, including the 1.4 MB responsive gallery and the 2.1 MB
   Chapter 5 render set. The heaviest are
   hospital-design-500-bed-healing-spaces.jpg (401 KB, 4267 px wide) and
   media-coverage-publication.png (1 MB). WebP + srcset would cut several MB
   and is the next real performance win.
5. No site-wide 404 page. Unknown URLs return the shell (the /blogs/:slug route
   does have a proper "story not available" state).
6. Mobile LCP is ~5 s on simulated slow 4G because the whole page is
   client-rendered — the LCP text cannot paint until React runs. Prerendering
   the public routes to static HTML would fix that; ask if you want it done.


ABOUT THE .map FILES
--------------------
`assets/*.js.map` exist for DevTools and for the "missing source maps" audit.
They are never fetched by visitors. If upload size matters, you can delete them
and the site works identically.
